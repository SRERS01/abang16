## Safe Verification Roadmap (Prioritized Checklist)
To audit this parameter map efficiently while respecting the 5 requests per second rate limit, prioritize your testing into three phases:
## Phase 1: High-Severity Logic Audits (IDOR)

* Target: Endpoints like /betting/bets-history?cda_id=... or /panel?cda_id=....
* Method: Authenticate two separate researcher sessions via your proxy suite. Extract the cda_id from Account B, and place it into a request using Account A’s authentication headers. If the response displays Account B's records, an access control failure exists.

## Phase 2: Structural Boundary Audits (SQLi & XSS)

* Target: Inputs like ?search= or ?id=.
* Method:
* For XSS: Submit safe string tokens like AUDITXSS"'< and analyze the browser's Document Object Model (DOM) to verify if characters are escaped into safe HTML entities.
   * For SQLi: Append logical boolean assertions (e.g., AND 1=1 vs AND 1=2) or a benign database latency check to see if query processing delays change.

## Phase 3: Matrix Token Decoupling (SSRF)

* Target: Base64 JSON strings inside redirect_data=.
* Method: Base64-decode the parameter payload, identify any internal destination string components (like domain references or redirect loops), swap them safely with a passive web monitor host (like an Interactsh address), re-encode, and review your logs for server-initiated network traffic.
