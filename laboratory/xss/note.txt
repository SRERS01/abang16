## Step-by-Step Safe Verification Framework
To test these entry points without breaking platform execution flows or exceeding the 5 requests per second throttling policy, follow a safe, gradual string breakout strategy.
## Step 1: Context Detection (Reflection Mapping)
Instead of starting with active execution payloads like <script>, use a benign, unique alphanumeric string to determine exactly where and how your text lands in the frontend source code.

* Action: Supply a specific tracking token, such as ?search=XSSREFLECTTEST1, to the target endpoint. Open your browser's Developer Tools (F12), navigate to the Elements or Source tab, and search for your token.
* Safe Observation: Note whether your string is embedded inside standard HTML text blocks, enclosed between attribute quotation marks (e.g., value="XSSREFLECTTEST1"), or placed inside an existing execution block like <script>var context = "XSSREFLECTTEST1";</script>.

## Step 2: Special Character Escape Check
Test if the backend or client-side sanitizers neutralize structural markup tags.

* Action: Append a harmless string containing essential HTML and JavaScript delimiter operators:
?search=XSSREFLECTTEST1"'>
* Safe Observation: Inspect the reflection point in the DOM source view. If the characters appear exactly as written ("'>), the context can be broken out of. If they are converted into safe HTML entities (like &quot;, &#39;, or &gt;), the context is properly protected.

## Step 3: Proving Execution Safely
If the delimiter check succeeds, verify full execution using non-intrusive operations. Never use loops that freeze browser tabs or scripts that access session local storage keys.

* Action: Inject a benign mathematical or functional command.
* Attribute Context Breakout: " autofocus onfocus=console.log(1) 
   * HTML Context Breakout: <u>Test</u> or <img src=x onerror=console.log(1)>
* Safe Observation: Check the Developer Tools Console tab. If the integer 1 is written to the log interface, execution is confirmed.
